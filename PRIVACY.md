# Privacy Policy

SSHive is a desktop application that runs entirely locally. This document describes what data it stores and what network connections it makes.

## Data stored locally

SSHive stores the following data on your machine only:

- **`~/.config/sshive/config.yaml`** — service names, connection parameters (host, user, port), references to SSH keys by UUID, deploy mode, backup-prompted status. Permissions: 0600.
- **`~/.config/sshive/secrets.yaml.gpg`** — API tokens and other secrets, encrypted with your GPG key. Readable only by the GPG key you selected at first launch.
- **`~/.ssh/sshive_<service>_<date>`** and **`.pub`** — SSH key pairs generated by SSHive. Private key permissions: 0600.
- **`~/.config/sshive/audit.log`** — append-only log of key generation, revocation, and service deletion events. Permissions: 0600.

## Network connections

SSHive makes **outgoing connections only**, initiated explicitly by you:

| Operation | Destination | Protocol | Condition |
|-----------|-------------|----------|-----------|
| Deploy key (automatic) | Your configured server | SSH (port 22 or custom) | SSH generic services |
| Verify connection | Your configured server | SSH | After automatic deployment |
| Revoke key | Your configured server | SSH | SSH generic services |
| Pre-flight token probe | `api.github.com` | HTTPS (443) | GitHub services, before rotation |
| Deploy key | `api.github.com` | HTTPS (443) | GitHub services only |
| Revoke key | `api.github.com` | HTTPS (443) | GitHub services only |
| Verify key | `api.github.com` | HTTPS (443) | GitHub services only |
| Pre-flight token probe | `gitlab.com` or your self-hosted URL | HTTPS (443) | GitLab services, before rotation |
| Deploy key | `gitlab.com` or your self-hosted URL | HTTPS (443) | GitLab services only |
| Revoke key | `gitlab.com` or your self-hosted URL | HTTPS (443) | GitLab services only |
| Verify key | `gitlab.com` or your self-hosted URL | HTTPS (443) | GitLab services only |

Services using `DeployMode::ExternalCm` (NixOS, Ansible, Puppet) make **no network connections** through SSHive.

All HTTPS connections use rustls with WebPKI certificate roots (no system certificate store, no native TLS).

SSHive never connects to Anthropic servers, analytics services, or any other third party. There is no telemetry, no crash reporting, and no update check.

## External processes

SSHive invokes the following local programs as subprocesses:

- `ssh-keygen` — key generation (passphrase re-encryption is done in-process via the `ssh-key` crate; no passphrase is passed as a command-line argument)
- `ssh-copy-id` — automatic key deployment (SSH generic services)
- `ssh` — connection verification and key revocation (SSH generic services)
- `xdg-open` — opens token creation URLs in the system browser (only when the user clicks "Ouvrir dans le navigateur" in the service form)
- `gpg` — secret encryption/decryption and key management
- `pinentry-*` — passphrase collection (runs in a separate window)

## Data you control

- All data is stored in standard locations under your home directory.
- Deleting `~/.config/sshive/` removes all SSHive configuration.
- SSH keys generated by SSHive are standard OpenSSH files; they can be used with any SSH client.
- The GPG-encrypted secrets file can be decrypted with `gpg --decrypt` using your own key.
